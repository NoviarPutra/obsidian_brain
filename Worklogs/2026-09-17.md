## 🛠️ `voldemort-vps` — Remediasi Insiden OmniRoute & Telemetri SQLite

Investigasi dan pemulihan insiden service OmniRoute (down/crash loop) dan error telemetri SQLite bot di `voldemort-vps`:

1. **Root Cause #1 (OmniRoute Crash Loop)**: Konfigurasi `NODE_OPTIONS` di `services/omniroute/docker-compose.yml` menyertakan flag `--optimize-for-size` yang ditolak runtime Node.js (`node: --optimize-for-size is not allowed in NODE_OPTIONS`). Ini memicu error `The model server is not responding` pada gateway Hermes.
2. **Root Cause #2 (SQLite Telemetry Read-Only Lock)**: Di `voldemort-menu-bot`, path `/home/voldemort/.omniroute` di-mount dengan mode `:ro`. SQLite WAL mode memerlukan akses shared memory (`-shm`) saat dibuka dengan `mode=ro` biasa, sehingga query SQLite gagal dengan `unable to open database file`.
3. **Remediasi & Eksekusi**:
   - Backup konfigurasi bertimestamp (`docker-compose.yml.bak.*` dan `omniroute_telemetry.py.bak.*`).
   - Perbaikan `NODE_OPTIONS=--max-old-space-size=1536` pada `docker-compose.yml` OmniRoute, deploy via `docker compose up -d`.
   - Patch `omniroute_telemetry.py` dengan URI parameter `mode=ro&immutable=1` untuk bypass shared memory lock pada container read-only mount, rebuild & deploy `voldemort-menu-bot`.
4. **Verifikasi**:
   - OmniRoute Health check: `HTTP 200 OK` (`/api/health`), `/v1/chat/completions` combo `AG` responsif sub-second.
   - Telemetri token: Status `success`, 7 node aktif normal (🟢), agregasi token akurat.
   - Gateway Hermes: Model endpoint normal dan stabil.
