3. **Remediasi & Eksekusi**:
   - Backup konfigurasi bertimestamp (`docker-compose.yml.bak.*` dan `omniroute_telemetry.py.bak.*`).
   - Perbaikan `NODE_OPTIONS=--max-old-space-size=1536` pada `docker-compose.yml` OmniRoute, deploy via `docker compose up -d`.
   - Patch `omniroute_telemetry.py` dengan URI parameter `mode=ro&immutable=1` untuk bypass shared memory lock pada container read-only mount, rebuild & deploy `voldemort-menu-bot`.

## ⚡ SRE — OmniRoute Admission Guard & CGroup Memory Latch Outage Resolution (`voldemort-vps`)
- **Root Cause & Latch Mechanism**:
  1. **OmniRoute CGroup Guard (`resourcePressurePolicy.ts`)**: OmniRoute mengevaluasi rasio memori CGroup Linux (`memory.current / memory.max`). Dengan limit container sebelumnya `1536M`, baseline memori Node.js + SQLite buffer (~1.33–1.38 GB) menyentuh 86–92% utilisasi CGroup.
  2. **The Latch Condition**: Saat ada request masuk (cron job watchdog `d01d706e7bd2` atau chat Telegram), rasio memori melewati `criticalRatio: 0.92`, memicu status `critical` (`reason: "cgroup_ratio"`). Untuk recovery, guard mewajibkan memori turun di bawah `recoveryRatio: 0.75` (1152 MB). Karena baseline memori container ~1.3 GB (> 1152 MB), OmniRoute terkunci secara permanen (*pinned*) dalam mode rejection dan mengembalikan HTTP 503 ke seluruh request.
  3. **Mengapa Local macOS Aman**: Di macOS (Darwin), path `/sys/fs/cgroup/` dan `/proc/pressure/` tidak ada (bernilai `null`), sehingga guard hanya mengevaluasi heap V8 murni tanpa restriksi CGroup.
- **Definitive Remediation**:
  - Konfigurasi `~/services/omniroute/docker-compose.yml` diperbarui: `limits.memory: 3072M` (3.0 GB), `NODE_OPTIONS=--max-old-space-size=2048`, `OMNIROUTE_MEMORY_MB=2048`, `HEAP_PRESSURE_THRESHOLD_MB=1800`, dan `OMNIROUTE_CHAT_ADMISSION_HEAP_SHED_RATIO=0.85` (backup: `docker-compose.yml.bak.20260917113305`).
- **Post-Deploy Observability & Verification**:
  - Utilisasi CGroup memori turun ke **44.3%** (`1.42 GB / 3.00 GB`), jauh di bawah batas 75% recovery.
  - Test request `/v1/chat/completions` (model `AG`) sukses 200 OK.
  - Script SRE watchdog `sre_watchdog.py` dieksekusi normal (`OK: Systems Normal`), menyelesaikan kegagalan cronjob `d01d706e7bd2`.
